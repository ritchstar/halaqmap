# ساحة الشطرنج — خارطة الطريق (Route: `/chess`)

هذا المستند يوثّق ما بُني في **المرحلة الأولى** (بما فيها ترقية التصميم ومحرك Stockfish الحقيقي)، وما تبقّى من عمل في المرحلتين اللاحقتين (الاشتراكات، ثم التشاركي). صفحة عامة قابلة للفهرسة (بلا `noindex`) — ليست معاينة داخلية.

## أ. ما تم بناؤه

### الأساس (اللعب + الجلسة)

- **صفحة هبوط + لعب في مسار واحد** (`src/pages/ChessArenaPage.tsx`، على `/chess`): هبوط + بطاقات اختيار المستوى عند عدم وجود مباراة جارية، ودخول مباشر للرقعة عند وجود جلسة محفوظة قيد اللعب.
- **رقعة مبنية يدوياً** (`src/components/chess/ChessBoardView.tsx`): شبكة 8×8 برموز يونيكود، تحديد بالنقر ثم نقر الوجهة (بلا سحب وإفلات، متوافقة مع الجوال)، مع إحداثيات الملفات (a–h) والرتب (1–8) حول الرقعة، وتظليل مربّعي آخر نقلة. لا تعتمد على أي مكتبة رقعة خارجية.
- **قواعد اللعبة عبر `chess.js`** (`chess.js@^1.0.0` في `package.json`): الشرعية، الكش، كش الملك، التعادل، الترقية، التبييت، الأخذ بالمرور.
- **حفظ الجلسة محلياً** (`src/lib/chessSessionLab.ts`): نمط «Lab State» — `localStorage` فقط، بلا حساب وبلا خادم. لافتة «تابع المباراة» تظهر عند إعادة فتح `/chess` ووجود مباراة قيد اللعب.
- **قرار تبسيط متعمد**: اللاعب يلعب بالأبيض دائماً (لا اختيار لون بعد).

### محركا الذكاء الاصطناعي (طبقة مزدوجة)

- **`src/lib/chessAi.ts`** — محرك محلي بالكامل (Minimax + تقليم Alpha-Beta + تعميق تكراري محدود بزمن)، بلا أي اعتمادية خارجية. يُستخدم دائماً لمستويي **مبتدئ** و**متوسط** (عمداً — راجع التعليل أدناه)، وهو أيضاً خط الرجوع الآمن لمستوى **محترف**.
- **`src/lib/stockfishEngine.ts`** — غلاف حول محرك **Stockfish** الحقيقي (حزمة `stockfish@^16.0.0`، بناء خفيف أحادي الخيط عبر Web Worker، **بلا** حاجة لـ SharedArrayBuffer أو ترويسات COOP/COEP خاصة على الاستضافة). يتواصل عبر بروتوكول UCI القياسي (`uci` → `uciok`، `isready` → `readyok`، `position fen ...`، `go movetime ...` → `bestmove ...`).
- **`src/lib/chessEngine.ts`** — طبقة القرار: مستوى **محترف** يستخدم Stockfish بأقصى قوة (`Skill Level 20`)؛ أي تعذّر (Worker لا يستجيب، ملف غير موجود، مهلة انتهت) يتراجع تلقائياً وبصمت للمحرك المحلي **بنفس المستوى** — اللعبة لا تتعطل أبداً مهما حدث مع Stockfish.
- **لماذا مبتدئ/متوسط لا يستخدمان Stockfish**: قرار تصميم متعمد — Stockfish بمستويات «Skill Level» منخفضة يلعب أخطاءً غريبة وغير طبيعية (نقلات عشوائية بالكامل أحياناً)، بينما محرك «الخطأ المتعمد» المحلي (احتمال مضبوط للعب نقلة عشوائية بدل الأفضل) يمنح تجربة أقرب لخصم مبتدئ حقيقي فعلاً. Stockfish بكامل قوته هو من يمثّل مستوى «محترف».

### ⚠️ خطوة تحتاج تحققاً بعد `npm install` — مهم

ملفات محرك Stockfish الثنائية (WASM/asm.js) **تُنسخ تلقائياً** من `node_modules/stockfish` إلى `public/stockfish/` عبر سكربت جديد يعمل تلقائياً بعد كل `npm install`:
- أضفته في `package.json`: `"postinstall": "node scripts/copy-stockfish-assets.mjs"`.
- السكربت (`scripts/copy-stockfish-assets.mjs`) **لا يفترض اسم ملف دخول بعينه** — ينسخ كل ملف صالح (`.js`/`.mjs`/`.wasm`/`.nnue`) موجود فعلياً داخل الحزمة المثبتة، لأن أسماء ملفات الدخول تختلف بين إصدارات حزمة `stockfish` على npm ولم أستطع التحقق من الاسم الدقيق للإصدار الذي سيُثبَّت فعلياً عندك (بيئة العمل هنا بلا اتصال بسجل npm).
- غلاف المحرك (`stockfishEngine.ts`) يجرّب بدوره عدة أسماء ملفات دخول مرشّحة شائعة (`stockfish.js`, `stockfish.wasm.js`, `stockfish-nnue-16-single.js`, …) عبر طلب `HEAD` قبل تشغيل الـ Worker.
- **بعد `npm install` الأول، افتح `/chess` واختر مستوى «محترف»، وتحقق من ظهور شارة «محرك Stockfish نشط» فوق الرقعة (لا «المحرك المحلي — Stockfish غير متاح الآن»).** إن ظهرت شارة المحرك المحلي رغم التثبيت الناجح، افتح أدوات المطوّر في المتصفح (Network) وتحقق من اسم الملف الفعلي داخل `public/stockfish/` بعد التثبيت، وأضفه إلى `CANDIDATE_ENTRY_FILES` في `src/lib/stockfishEngine.ts` إن لم يكن من الأسماء المجرَّبة أصلاً — تعديل سطر واحد. **حتى لو لم يُضبط هذا مباشرة، الموقع يعمل بشكل طبيعي كاملاً** (اللعب يستمر بالمحرك المحلي بصمت)، فقط قوة مستوى «محترف» تبقى أقل مما هي مصمَّمة له حتى يُصحَّح المسار.

### التصميم والتجربة

- **إحداثيات الرقعة** (ملفات/رتب) وإطار خشبي حول الرقعة.
- **تظليل آخر نقلة** على مربّعي الانطلاق والوصول.
- **شريط القطع المأسورة وميزان المادة** (`src/components/chess/ChessCapturedTray.tsx`) — يُحسب من سجل النقلات مباشرة، يعرض من تقدّم بالمادة وبكم.
- **سجل نقلات مُرقَّم بأزواج قياسية** (1. e4 e5 2. Nf3 …) في بطاقة قابلة للتمرير (`src/components/chess/ChessMoveList.tsx`).
- **بطاقة نتيجة** (`src/components/chess/ChessResultOverlay.tsx`) تظهر فوق الرقعة عند انتهاء المباراة (فوز/خسارة/تعادل/استسلام) بأيقونة مناسبة وزر «مباراة جديدة» مباشر، بدل الاكتفاء بنص حالة فقط.
- **أصوات خفيفة قابلة للكتم** (`src/lib/chessSound.ts`) — نغمات مولَّدة عبر Web Audio API مباشرة (بلا أي ملف صوتي خارجي): نقلة، أسر قطعة، كش، نهاية مباراة. تفضيل الكتم محفوظ محلياً، وزر تبديل ثابت في رأس الصفحة.
- **شارة المحرك المستخدم فعلياً** («محرك Stockfish نشط» / «المحرك المحلي») تظهر لمستوى «محترف» فقط — شفافية للمستخدم بدل الادّعاء الصامت.

## ب. تعليمات المعاينة

بعد `npm install` (سيسحب `chess.js` و`stockfish` الجديدين، وينسخ أصول Stockfish تلقائياً عبر `postinstall`)، شغّل `npm run dev` وافتح `/chess`. جرّب: مستوى «محترف» + تحقق من شارة المحرك (راجع القسم أعلاه) → العب حتى كش ملك أو تعادل ولاحظ بطاقة النتيجة والأصوات → جرّب زر كتم الصوت → أغلق التبويب وأعد فتح `/chess` للتأكد من ظهور لافتة «تابع المباراة».

## هـ. ملاحظات عامة

- لا اختبارات آلية مضافة في هذه المرحلة (لا يوجد إطار اختبار E2E جاهز في المشروع لصفحات مماثلة). يُنصح باختبار يدوي شامل: كش الملك، التعادل بالجمود، الترقية، الاستسلام، استئناف الجلسة بعد إغلاق التبويب فعلياً (لا مجرد تنقّل SPA)، وتحديداً **التحقق من عمل Stockfish فعلياً** (القسم أ أعلاه).
- المحرك المحلي يعمل تزامنياً على الخيط الرئيسي (لا Web Worker)؛ Stockfish يعمل في Worker منفصل فلا يجمّد الواجهة أثناء تفكيره حتى عند مستوى «محترف».
- لا رابط للصفحة من الرئيسية أو أي قائمة بعد — قرار مكانها التسويقي (رئيسية؟ صفحة المتجر؟ حملة مستقلة؟) متروك لك.
