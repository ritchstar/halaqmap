# تشخيص: اختفاء صورة منتج تمرتنا1 بعد ظهورها

**التاريخ:** 11 سبتمبر 2026
**الطريقة:** قراءة مباشرة لكود `StoreDatesIngest.tsx` و`storeDatesLiveLab.ts` و`StoreDatesShop.tsx`، ومقارنتها بالنمط الذي يعمل فعلياً في كافينا1/مطعمنا1/طبختنا1 — وليس تخميناً.

---

## السبب الجذري (مؤكَّد من الكود)

**منتج تمرتنا1 لا يملك أصلاً أي حقل لحفظ صورة لكل صنف.** فحصت النوع البرمجي للصنف:

```ts
// src/lib/storeDatesLiveLab.ts
export type DatesShelfItem = {
  catalogId: string;
  nameAr: string;
  category: string;
  unit: StoreDatesUnit;
  price: number;
  inStock: boolean;
  arrivedToday: boolean;
  featured: boolean;
  // لا يوجد photoSrc هنا إطلاقاً
};
```

بالمقارنة، كافينا1 ومطعمنا1 وطبختنا1 لديها `photoSrc?: string` في نوع الصنف، بالإضافة لدالة `setPhoto(catalogId, file)` حقيقية تحفظ الصورة (مضغوطة عبر `compressImageFile`) داخل `state.shelf` مباشرة.

**تمرتنا1 لا تملك أياً من هذين.** المربع الوحيد الذي يبدو وكأنه "رفع صورة" في شاشة إدخال تمرتنا1 (`StoreDatesIngest.tsx`) هو هذا:

```tsx
const [listPhoto, setListPhoto] = useState('');
...
<input type="file" accept="image/*" onChange={(e) => {
  const file = e.target.files?.[0];
  if (!file) return;
  const reader = new FileReader();
  reader.onload = () => setListPhoto(String(reader.result || ''));
  reader.readAsDataURL(file);
}} />
{listPhoto ? <img src={listPhoto} ... /> : null}
```

هذا المربع **مقصود أصلاً فقط كمرجع بصري مؤقت يساعد صاحب النشاط وهو يكتب قائمة أصنافه نصاً يدوياً** (نفس الفكرة موجودة بنفس الشكل في كافينا1/مطعمنا1 كمساعدة مرجعية) — **وليس مخصصاً لحفظ صورة المنتج**. المشكلة: في تلك المنتجات الثلاثة يوجد بجانبه زر فعلي منفصل لحفظ صورة كل صنف، بينما في تمرتنا1 **لا يوجد ذلك الزر إطلاقاً** — فيبدو لصاحب النشاط أن هذا المربع هو "رفع صورة المنتج".

**ما يحدث فعلياً خطوة بخطوة:**
1. صاحب النشاط يضغط رفع صورة → الصورة تظهر فوراً كمعاينة (`reader.onload`) — هذا هو "الظهور".
2. يضغط "احفظ الصفوف بعد المراجعة" → دالة `applyList()` **لا تستخدم `listPhoto` إطلاقاً** في أي مكان — تُعالج فقط النص المكتوب، والصورة **لا تُحفظ لا في `state.shelf` ولا يُرسل أي شيء للخادم**.
3. عند تحديث الصفحة، أو الانتقال لتبويب آخر ثم العودة، أو حتى مجرد إعادة عرض المكوّن — `listPhoto` (وهو حالة محلية بحتة `useState`) تعود فارغة تلقائياً لأنها لم تُحفظ أبداً في أي مكان دائم. هذا هو "الاختفاء".

---

## الحل المقترح

### أ) الحل الفوري (بدون تعديل كود) — لصاحب النشاط الآن
لا توجد حالياً أي طريقة لإرفاق صورة حقيقية دائمة لصنف في تمرتنا1 — الميزة غير مكتملة. مربع "رفع صورة" الحالي للمرجع الشخصي فقط أثناء كتابة القائمة، ولن تظهر أبداً للزبائن حتى لو بقيت المعاينة على الشاشة.

### ب) الحل البرمجي (لكروسور) — نسخ نفس نمط كافينا1 الذي يعمل فعلياً
1. إضافة `photoSrc?: string` إلى `DatesShelfItem` في `storeDatesLiveLab.ts`.
2. إضافة دالة `setPhoto(catalogId, file)` في `StoreDatesIngest.tsx` مطابقة تماماً لما في `StoreCafeMenuBoard.tsx` (السطور 55-65 هناك) — علماً أن `compressImageFile` **مستوردة بالفعل** في `storeDatesLiveLab.ts` (سطر 20) ولم تُستخدم بعد لهذا الغرض.
3. إضافة زر/مدخل رفع صورة فعلي لكل صنف في قائمة `StoreDatesIngest.tsx` (بجانب زر "تفعيل") يستدعي `setPhoto`.
4. تعديل `DatesShelfCard` في `StoreDatesShop.tsx` ليُفضّل `item.photoSrc` الحقيقي إن وُجد، ويعود للصور المخزنية الدورية (`datesCatalogImage`) فقط إن لم توجد — بنفس منطق الأولوية المستخدم أصلاً في `liveActivityCoverSrc` (`src/lib/storeLiveActivityShelf.ts`).
5. (اختياري لكن موصى به) توضيح نص صريح فوق مربع "صورة القائمة" الحالي يقول إنه للمرجع الشخصي فقط ولا يُحفظ ولا يظهر للزبائن — لتفادي نفس اللبس مستقبلاً في المنتجات المشابهة.

**ملاحظة سياقية:** هذا يتقاطع تماماً مع فجوة "غياب `photoSrc` في تمويناتا1/خضارنا1" التي رصدناها سابقاً في نقاش تطوير جار الحي — تمرتنا1 تعاني من نفس الفجوة بالضبط، بنفس الحل (نسخ نمط طبختنا1/كافينا1). يستحق تنفيذ الإصلاح لكل المنتجات الثلاثة (تمرتنا1، تمويناتا1، خضارنا1) دفعة واحدة بما أنها نفس الكود المكرر ونفس الإصلاح حرفياً.
