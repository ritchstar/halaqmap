# تسليم: إعادة تصميم بطاقات فهرس "خريطة الحل" — بطاقة صورة كاملة لكل منتج

**التاريخ:** 2026-09-11
**الحالة:** هذا التسليم **يلغي ويحل محل** الحل السابق الموثّق في `catalog_product_images_handoff.md` (مكوّن `ProductMark` الصغير). لا داعي لتنفيذ ذلك الملف — تم تجاوزه بالكامل بهذا التصميم الأشمل.

---

## الفكرة

بدل شارة/شعار صغير (88px) بجانب نص المنتج، أصبحت البطاقة **بأكملها صورة تعبيرية واحدة** تمثّل هوية/نشاط المنتج الفعلي، مع اسم المنتج مركّبًا فوقها بخط يمزج بين الطابع الكلاسيكي (الجزء العربي من الاسم) والطابع الحديث (الرقم/اللاحقة إن وجدت)، فوق تدرّج داكن يضمن وضوح القراءة. تنطبق على المنتجات العشرة كلها بنفس النمط.

## الكود جاهز فعلاً لمشروعنا (Vite + React Router)

بخلاف تسليم `ProductMark` السابق الذي استخدم `next/image`، هذا الكود **تم تصحيحه مسبقًا** ليطابق المشروع الفعلي:

- `<img>` عادي مع `object-fit: cover` بدل `next/image`.
- `<Link>` من `react-router-dom` بدل أي تنقّل خاص بـ Next.

يمكن نسخه كما هو دون أي تعديل بنيوي.

### `SolutionCatalogProductCard.tsx`

```tsx
import { Link } from "react-router-dom";
import "./SolutionCatalogProductCard.css";

type SolutionCatalogProduct = {
  code: string;
  name: string;
  latinName: string;
  imageSrc: string;
  category: string;
  summary: string;
  to: string;
};

type SolutionCatalogProductCardProps = {
  product: SolutionCatalogProduct;
  onOpen?: (product: SolutionCatalogProduct) => void;
};

export function SolutionCatalogProductCard({
  product,
  onOpen,
}: SolutionCatalogProductCardProps) {
  const content = (
    <article className="solution-card">
      <img
        className="solution-card__image"
        src={product.imageSrc}
        alt={`صورة ${product.name}`}
        loading="lazy"
      />
      <div className="solution-card__wash" aria-hidden="true" />
      <div className="solution-card__meta">
        <span className="solution-card__code">{product.code}</span>
        <span className="solution-card__category">{product.category}</span>
      </div>
      <div className="solution-card__content">
        <span className="solution-card__latin">{product.latinName}</span>
        <h3 className="solution-card__title">
          <span className="solution-card__title-classic">
            {product.name.replace(/[0-9]/g, "")}
          </span>
          {product.name.match(/[0-9]/)?.[0] ? (
            <span className="solution-card__title-modern">
              {product.name.match(/[0-9]/)?.[0]}
            </span>
          ) : null}
        </h3>
        <p className="solution-card__summary">{product.summary}</p>
      </div>
    </article>
  );

  if (onOpen) {
    return (
      <button
        type="button"
        className="solution-card-button"
        onClick={() => onOpen(product)}
        aria-label={`فتح تفاصيل ${product.name}`}
      >
        {content}
      </button>
    );
  }

  return (
    <Link
      to={product.to}
      className="solution-card-link"
      aria-label={`فتح ${product.name}`}
    >
      {content}
    </Link>
  );
}
```

### `SolutionCatalogProductCard.css`

(انسخ الملف المرفق `SolutionCatalogProductCard.css` كما هو — يحتوي على: خلفية الصورة كاملة، تدرّج `wash` غامق أسفل البطاقة لوضوح النص، عنوان بخطين (`title-classic` للاسم العربي بخط Georgia/Times، و`title-modern` للرقم بخط Arial بلون التمييز)، وتأثير تكبير خفيف للصورة عند المرور بالماوس.)

## خطوات الدمج في المشروع الفعلي

### 1. نسخ الملفات

- انسخ `SolutionCatalogProductCard.tsx` و`SolutionCatalogProductCard.css` إلى `src/components/store/catalog/` (أو المجلد الذي يحوي مكوّنات الفهرس الحالية).
- انسخ مجلد `images/` بالكامل إلى `public/images/` (بحيث يصبح المسار النهائي مثلاً `public/images/halaqmap-a-01.webp`).

### 2. تحديث `src/config/storeSolutionCatalog.ts`

بنية المنتج الحالية تحتوي على حقول مثل `code`, `name`, `latin`, `category`, `segment`, `logoSrc`, `accent`, `summary`, `description`, `tags`, `href` (و`external` لبعض المنتجات — راجع `catalog_href_routing_fix.md`، وبعد تنفيذه لم يعد أي منتج من العشرة يستخدم `external: true`).

أضف حقلاً جديدًا لكل منتج (أو أعد تسمية/استخدام حقل موجود إذا رأى كروسور أنسب) يحمل مسار الصورة الجديدة:

```ts
{
  code: "A-01",
  name: "حلاق ماب",
  latin: "HalaqMap",
  // ... الحقول الموجودة كما هي
  heroImage: "/images/halaqmap-a-01.webp", // ← حقل جديد
}
```

جدول المطابقة الكامل (كود المنتج ← اسم ملف الصورة):

| الكود | المنتج | اسم ملف الصورة |
|---|---|---|
| A-01 | حلاق ماب | `halaqmap-a-01.webp` |
| A-02 | كوافير ماب | `coiffeurmap-a-02.webp` |
| B-01 | خضارنا1 | `khodarna1-b-01.webp` |
| B-02 | تمويناتا1 | `tamwinata1-b-02.webp` |
| C-01 | مطعمنا1 | `matamna1-c-01.webp` |
| C-02 | كافينا1 | `cafena1-c-02.webp` |
| D-01 | لاونجا1 | `launja1-d-01.webp` |
| D-02 | أفراحي1 | `afrahi1-d-02.webp` |
| D-03 | أجواء1 | `ajwa1-d-03.webp` |
| E-01 | كاردي8 | `cardi8-e-01.webp` |

### 3. تحديث `SolutionCatalogApp.tsx`

استبدل عرض بطاقة/صف المنتج الحالي (سواء كان التصميم القديم بعمود 88px، أو مكوّن `ProductMark` إن كان قد نُفّذ سابقًا) باستدعاء المكوّن الجديد لكل منتج ضمن حلقة العرض:

```tsx
import { SolutionCatalogProductCard } from "@/components/store/catalog/SolutionCatalogProductCard";

// ... داخل الحلقة التي تعرض المنتجات:
<SolutionCatalogProductCard
  product={{
    code: product.code,
    name: product.name,
    latinName: product.latin,
    imageSrc: product.heroImage,
    category: product.category,
    summary: product.summary,
    to: product.href,
  }}
/>
```

- إن كان الفهرس يفتح نافذة تفاصيل (`ProductModal`) بدل التنقل المباشر عند الضغط، مرّر `onOpen={handleOpenProduct}` بدل الاعتماد على `to` — المكوّن يتعامل مع الحالتين تلقائيًا (يعرض `<button>` بدل `<Link>` عند وجود `onOpen`).
- تخطيط الشبكة (grid) المحيط بالبطاقات في `SolutionCatalogApp.tsx`/CSS الحالي يبقى كما هو غالبًا؛ فقط تأكد أن حاوية كل بطاقة لا تفرض ارتفاعًا يقل عن `23rem` (القيمة المضبوطة في `.solution-card` نفسها عبر `min-height`) حتى لا تُقصّ الصورة.

### 4. حذف/تعطيل الكود القديم

إن كان مكوّن `ProductMark` (من `catalog_product_images_handoff.md`) قد نُفّذ فعليًا، احذف استدعاءاته من `SolutionCatalogApp.tsx` و`ProductModal` — لم يعد له استخدام بعد اعتماد البطاقة الكاملة الجديدة. الملف نفسه يمكن حذفه أو تركه غير مستخدم حسب تفضيل الفريق.

### 5. التحقق النهائي

- تأكد أن فحص الأنواع (`tsc`) لا يظهر أخطاء بعد إضافة الحقل الجديد `heroImage` (أو أي اسم بديل) إلى نوع `SolutionCatalogProduct`.
- افتح صفحة الفهرس محليًا وتأكد أن كل بطاقة من العشرة تعرض صورتها الصحيحة مطابقة للجدول أعلاه، وأن اسم المنتج يظهر بوضوح فوق التدرّج الغامق أسفل كل بطاقة.
- تأكد أن الضغط على كل بطاقة يوجّه للمسار الصحيح (`/partners` لحلاق ماب، `/coiffeur` لكوافير ماب، وصفحات العرض الداخلية لبقية المنتجات كما في `catalog_href_routing_fix.md`).

## ملاحظة على مصدر الصور

الصور العشر توليد أصلي (AI-generated) من شاتلي، بأسلوب تعبيري موحّد يعكس نشاط كل منتج فعليًا (صالون حلاقة، صالون تجميل نسائي، خضار وفواكه، بقالة، مطعم، كافيه، صالة أفراح/لاونج، محل ورود/مناسبات، أجواء عامة، بطاقات معايدة) — وليست صورًا فوتوغرافية حقيقية لمحال قائمة. إذا رغب الفريق لاحقًا باستبدال أي صورة بصورة حقيقية للمحل الفعلي، يكفي استبدال ملف الـ WebP بنفس الاسم في `public/images/` دون أي تعديل على الكود.
